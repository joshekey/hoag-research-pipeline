# Two backend review tracks (1.50)

batch_review_tracks.py reads the existing bundle inventory. It computes groups
against the ENTIRE cohort first, preserving global identity/collision holds,
then diagnoses only the technical_holds_only lane. It does not recompute identity
eligibility on an isolated subset. For the current inventory this targets 321
studies/64,897 held paths, excluding partial standard/variation-study holds.
Actual current counts are printed; no expected numbers are hard-coded.

Exact reason counts and reason combinations distinguish policy from data evidence.
Current headers can reveal missing annotation flags, overlay metadata without
detected payload/bit-position tags, whitespace-normalization candidates, age
format issues and inventory/header disagreement. Issuer-only missing identity
is explicitly counted as a strict-policy hold, not proven wrong-patient data.
These observations are NOT confirmed parser defects or automatic clearance.
Missing flags/overlay descriptors do not prove pixels are safe; equally they do
not prove PHI is present. Decode/pixel-content investigation is not performed.
Historical generic source errors cannot be reconstructed from lost error detail.

--inspect-headers rereads held-file headers only. --verify-source-hashes additionally
reads complete held files to establish whether they match inventory SHA256; without
it, observations describe current headers and cannot establish unchanged content.
All originals, metadata, holds and approvals remain untouched.

The standard-review track creates standard-review-batches.private.csv and private
details in review-tracks.private.json. Up to ten study groups per work batch,
preserving the queue order (fully eligible before partial, smaller eligible scopes
first). This organizes work, not approval. With 101 groups there are 11 work batches.
Each row has reviewer/evidence-reference fields and unreviewed identity, profile
and all-frame checkpoints. Editing worksheets cannot grant authority.

Review procedure:
1. Assign a work batch to an authorized local reviewer. Use its private eligible
   source objects/hashes to establish exact image coverage. Keep held objects out.
2. Verify each group's patient membership using authoritative patient records,
   including differing namespaces/history when present. Names/paths/ages are not
   sufficient. No within-study variation does not prove cross-study identity.
3. Reference the explicitly approved profile and original PatientAge handling.
   A common approved profile artifact may be reused across reviewed groups.
4. Document all-frame burned-in/overlay/identifying-feature review for eligible
   objects. No automatic all-frame signoff is generated by these tools.
5. Keep the 28 variation studies and all held objects in separate investigations.
   Record evidence references locally; use the controlled authorization tool only
   after evidence is complete, targeting source_bundle_run, not this new diagnostic
   output directory. Do not authorize anything from aggregate counts alone.

Evidence directories 0700/files 0600; all detailed data remains hospital-local.
The terminal contains only aggregates. All 80 patients remain included; absent
patients are not excluded, reports are not required, P### grouping is unchanged.
This tool does not stage, anonymize, export, modify the database or change mounts.
No delivery to /mnt/hoag-output. Rollback is to stop using the diagnostic and retain
private worksheets for audit; no operational-state rollback is needed.
